# Отчёт по лабораторной работе № 6
## Разработка микросервиса с использованием Go kit и gRPC

**Вариант:** 6 — микросервис сотрудников (Employee).

## 1. Цель работы

Получить практические навыки проектирования и реализации микросервисного приложения на Go: выделить бизнес-логику в отдельный слой, организовать взаимодействие с сервисом через HTTP API и gRPC, описать контракт с помощью Protocol Buffers и проверить корректность работы сервиса.

## 2. Задание

Разработать сервис для работы с сотрудниками. Сервис должен поддерживать создание сотрудника, получение информации по идентификатору и изменение должности. Для доступа к одной бизнес-логике должны быть доступны HTTP- и gRPC-транспорты. Для gRPC необходимо использовать Go kit и контракт Protocol Buffers.

## 3. Описание предметной области

Основная сущность — `Employee`. Она содержит следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | уникальный идентификатор сотрудника |
| `full_name` | string | ФИО сотрудника |
| `position` | string | должность |
| `salary` | float64 | заработная плата |
| `hired_on` | int64 | дата найма в формате Unix timestamp |

Сервис предоставляет три основные операции:

- создание сотрудника и возврат его идентификатора;
- получение сотрудника по идентификатору;
- изменение должности существующего сотрудника.

## 4. Архитектура приложения

Приложение разделено на несколько логических частей:

- **Модель и репозиторий (`employee.go`).** Описывают сущность сотрудника, интерфейс хранилища и реализацию репозитория в памяти процесса.
- **Бизнес-слой (`service.go`).** Определяет интерфейс и реализацию операций над сотрудниками. Транспортные обработчики обращаются к этому слою, а не реализуют бизнес-правила самостоятельно.
- **HTTP-транспорт (`http.go`).** Принимает JSON-запросы и возвращает HTTP-ответы.
- **Go kit и gRPC (`grpc.go`).** Преобразуют gRPC-запросы в вызовы бизнес-сервиса через endpoints Go kit и формируют ответы.
- **Контракт (`employee.proto`).** Описывает сообщения и методы сервиса. Сгенерированные Go-типы и интерфейсы находятся в каталоге `gen/employee/v1`.
- **Точка входа (`main.go`).** Создаёт общий экземпляр сервиса, запускает HTTP- и gRPC-серверы и обеспечивает корректное завершение работы.

HTTP-сервер по умолчанию слушает порт **8080**, gRPC-сервер — порт **9090**. Оба транспорта используют общую бизнес-логику и репозиторий.

## 5. Реализация HTTP API

Команды ниже рассчитаны на **Windows PowerShell** (терминал VS Code можно открыть через **Terminal → New Terminal**).

Реализованы следующие маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/employees` | создание сотрудника |
| GET | `/employees/{id}` | получение сотрудника по ID |
| PATCH | `/employees/{id}/position` | изменение должности |
| GET | `/healthz` | проверка доступности HTTP-сервера |

При некорректном запросе возвращается ошибка клиента, а при попытке получить отсутствующего сотрудника — статус `404 Not Found`. Запросы передаются в формате JSON.

Пример создания сотрудника:

```powershell
$body = @{
    full_name = "Иван Иванов"
    position  = "Инженер"
    salary    = 80000
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:8080/employees" -Method Post -ContentType "application/json" -Body $body
```

Получение сотрудника (вместо `1` нужно подставить ID из ответа):

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/employees/1" -Method Get
```

Изменение должности:

```powershell
$body = @{
    position = "Ведущий инженер"
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:8080/employees/1/position" -Method Patch -ContentType "application/json" -Body $body
```

Проверка состояния сервера:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/healthz" -Method Get
```

**СКРИНШОТ ЗДЕСЬ**

## 6. Реализация gRPC с использованием Go kit

Контракт gRPC описан в файле `employee.proto`. Он содержит типизированные запросы и ответы для операций создания сотрудника, получения по ID и изменения должности. На основе контракта с помощью генераторов Protocol Buffers создаются Go-типы и клиентский/серверный интерфейс.

Go kit endpoints связывают транспорт с бизнес-сервисом. gRPC-адаптер декодирует входные сообщения, вызывает соответствующий endpoint, преобразует результат в protobuf-ответ и переводит ошибки предметной области в gRPC-коды:

- некорректные аргументы — `InvalidArgument`;
- сотрудник не найден — `NotFound`;
- непредвиденная внутренняя ошибка — `Internal`.

Для проверки можно использовать установленную утилиту `grpcurl`. Команды ниже записаны для **Windows PowerShell** и размещены в одну строку, чтобы не использовать Bash-символ продолжения `\\`. Сервер не требует включённого reflection, поэтому контракт передаётся явно:

```powershell
grpcurl -plaintext -import-path . -proto employee.proto -d '{"full_name":"Иван Иванов","position":"Инженер","salary":80000}' localhost:9090 employee.v1.EmployeeService/Create
```

Для получения сотрудника:

```powershell
grpcurl -plaintext -import-path . -proto employee.proto -d '{"id":"1"}' localhost:9090 employee.v1.EmployeeService/GetByID
```

Для изменения должности:

```powershell
grpcurl -plaintext -import-path . -proto employee.proto -d '{"id":"1","position":"Ведущий инженер"}' localhost:9090 employee.v1.EmployeeService/ChangePosition
```

ID в примере необходимо заменить на ID, полученный при создании сотрудника в текущем запуске.

## 7. Запуск и тестирование

Для запуска и проверки приложения используются команды:

```powershell
go mod download
go test -race ./...
go vet ./...
go run .
```

Команда `go test -race ./...` запускает тесты с обнаружением гонок данных. В репозитории есть тесты бизнес-логики и интеграционный тест gRPC, проверяющий основные операции.

Адреса серверов можно переопределить параметрами запуска:

```powershell
go run . -http.addr=:8081 -grpc.addr=:9091
```

## 8. Результаты работы

В ходе работы реализован микросервис сотрудников с общей бизнес-логикой и двумя транспортами: HTTP и gRPC. HTTP API принимает JSON, а gRPC API использует типизированный protobuf-контракт и endpoints Go kit. Добавлены проверки ошибок и тесты основных сценариев.

Хранилище реализовано в памяти процесса, поэтому созданные записи не сохраняются после перезапуска приложения. Для промышленного использования можно подключить постоянную базу данных, аутентификацию, авторизацию и TLS.

## 9. Вывод

В результате лабораторной работы получены практические навыки разработки микросервисов на Go, разделения бизнес-логики и транспортного слоя, описания API с помощью Protocol Buffers и использования Go kit для построения gRPC-транспорта. Проверка через HTTP-запросы, gRPC-вызовы и автоматические тесты позволяет подтвердить корректность основных операций сервиса.
